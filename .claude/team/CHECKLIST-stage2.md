# Чек-лист ручной проверки этапа 2 (T-210…T-216)

Всё ниже проверяется на экспортированной сборке `build/DeskHero.app`. Автоматически эти пункты НЕ проверены: тесты GUT покрывают логику паутины, мост `Hero` и чистые функции `Overlay` без окна, но не окно, клики сквозь, мониторы, Spaces, Dock и реальное смахивание курсором. Замеры CPU на `.app` сделаны без мыши, числа в разделе «Покой и CPU» и в report T-216. Drag не замерен.

Строка «Если нет» говорит, что делать при провале. Запиши, что именно увидел. Единицы ниже в pt (на macOS lpx равен pt).

Из корня проекта, fish. Нужны шаблоны экспорта 4.7.2.
```fish

```
- [ ] Через 1-2 с герой появляется и встаёт на нижний край над Dock. Значка в Dock и в Cmd+Tab нет.
- [ ] Запасной выход всегда работает: `pkill -f DeskHero.app; pgrep -fl DeskHero` (вывод пустой).

## Как быстро вызвать нужное поведение
По умолчанию вылазка случается редко (шанс 25% при каждом конце паузы, не чаще раза в 180 с), плетение начинается после 300 с без твоего вмешательства. Для проверки ускорь в `.tres` и верни обратно. Через `git checkout` НЕ возвращай: в `resources/hero_balance.tres` лежат несохранённые в git правки этапа 2.
```fish
cp resources/hero_balance.tres /tmp/hero_balance.orig.tres
# частые вылазки: пауза 3-5 с, вылазка каждый раз, без интервала
sed -i '' -e 's/^idle_pause_min_sec = .*/idle_pause_min_sec = 3.0/' -e 's/^idle_pause_max_sec = .*/idle_pause_max_sec = 5.0/' -e 's/^web_trip_chance = .*/web_trip_chance = 1.0/' -e 's/^web_trip_min_interval_sec = .*/web_trip_min_interval_sec = 5.0/' resources/hero_balance.tres
godot --headless --path . --export-release macOS build/DeskHero.app; and open build/DeskHero.app
# вернуть как было
cp /tmp/hero_balance.orig.tres resources/hero_balance.tres; git diff --stat resources/hero_balance.tres
```
Для раскачки без спусков добавь `web_descent_chance = 0.0`, для одних спусков `1.0`. Для плетения см. раздел «Плетение». Не забудь вернуть значения: проверь `grep -E 'idle_pause|web_trip|weave_idle|web_descent' resources/hero_balance.tres` (ожидаются 15.0/45.0, 0.25, 180.0, 300.0, 0.25).

## Смахивание
Нужна паутина хотя бы в одном углу (см. «Плетение»). Кнопка мыши НЕ нужна.
- [ ] Быстрый взмах курсором через паутину (порядка 0.2 с на пересечение; опрос раз в 0.2 с, движение, которое остановилось сразу после взмаха, может не засчитаться): часть нитей отваливается и падает с затуханием около 0.5 с.
- [ ] Медленное движение курсора через паутину (около 1 с на пересечение): ничего не смахивает.
- [ ] Когда остаётся меньше 35% показанных нитей, весь угол обваливается и после этого может сплестись заново.
- [ ] Взмах мимо углов (по середине экрана) героя и паутину не трогает; CPU не растёт.
- [ ] Курсор, остановившийся на углу экрана ровно в (0, 0) (левый верхний пиксель основного монитора), смахивание не делает: ожидаемое ограничение (D-012, п. 5).
- Если нет: запиши скорость движения (быстро, медленно) и угол. Порог скорости `sweep_min_speed` (500 pt/с), радиус `sweep_hit_px` (14 pt), период опроса `cursor_poll_sec` (0.2 с).
