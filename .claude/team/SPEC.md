# DeskHero — структурированное ТЗ

Рабочая выжимка для команды. Первоисточник — [docs/SPEC.md](../../docs/SPEC.md): при расхождении прав он. Раздел `§N` — ссылка на него.

## Цель

Кросс-платформенный десктопный питомец: маленький оригинальный супергерой-паутинщик живёт поверх окон, ходит по краям экрана, качается на паутине и реагирует на пользователя и систему. Максимум интерактива при минимальной нагрузке. Распространение — только GitHub (Releases + сборка из исходников).

## Пользователи

Обычные пользователи macOS, Windows и Linux X11, которым нужен «живой» компаньон на рабочем столе и которые не должны замечать его в обычной работе.

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | В покое < 1–2% CPU на M1; 30 FPS при активности, 5–10 в покое/сне, `low_processor_mode` где возможно |
| NFR-2 | Недоступная платформенная фича тихо выключается и не роняет приложение |
| NFR-3 | Приложение никогда не ходит в сеть: ни телеметрии, ни аналитики, ни автообновлений |
| NFR-4 | Файлы пользователя удаляются только через `OS.move_to_trash()` |
| NFR-5 | Сохранения в `user://`, JSON, атомарно; логи в `user://logs/` с ротацией |
| NFR-6 | Персонаж и все ассеты оригинальны, без отсылок к чужим персонажам и ассетов из интернета |
| NFR-7 | Retina и масштаб 125–200% на Windows; архитектура не мешает мульти-мониторам позже |
| NFR-8 | Системные метрики опрашиваются раз в 5–60 с, не каждый кадр |
| NFR-9 | Логика покрыта тестами GUT; платформозависимое живёт только в `scripts/platform/` и `native/` |

## Вне рамок

Разговор через нейросеть, любые сетевые функции, чужие персонажи, Wayland-обходы до релиза, подпись сборок, мульти-мониторы на этапе 0.

## Допущения

- Godot 4.7.2 (актуальная в brew на 2026-10-30), GDScript со статической типизацией.
- Каждый этап — отдельная группа задач, следующая открывается только после подтверждения пользователя.
- Ручная проверка оверлея за пользователем: агенты не проверяют поведение поверх чужих окон, Spaces и Dock надёжно из headless-режима.
- Настоящий Dock/Cmd+Tab проверяется только на экспортированной сборке, запуск из редактора этого не покажет.

## Открытые вопросы

1. **Spaces на этапе 0.** Godot, скорее всего, не даёт поставить окну `NSWindowCollectionBehaviorCanJoinAllSpaces`, а GDExtension по ТЗ начинается с этапа 5. Если проверка это подтвердит, нужен минимальный нативный модуль уже на этапе 0. Решает пользователь после T-004.
2. **Drag-and-drop при passthrough.** Попадёт ли `files_dropped` в окно, если файл бросают на героя в прозрачном режиме. Проверить на этапе 6 или раньше небольшим спайком.
3. **Passthrough при 5–10 FPS.** Полигон может отставать от героя в покое. Измерить на этапе 0.
4. **C++ или Rust** для GDExtension — решение на этапе 5 с обоснованием в `docs/DECISIONS.md`. Сейчас на машине нет ни `cmake`, ни `cargo`.
