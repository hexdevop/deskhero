# DeskHero — правила работы

## Проект

DeskHero — десктопный питомец: маленький оригинальный супергерой-паутинщик, который живёт поверх рабочего стола, раскачивается на паутине между окнами и реагирует на пользователя и систему.

**Полное ТЗ и этапы: `docs/SPEC.md`. Прочитай его целиком перед началом любой работы.** Выжимка с FR/NFR: `.claude/team/SPEC.md`, архитектура: `.claude/team/ARCHITECTURE.md`, задачи: `.claude/team/PLAN.md`.

## Стек и команды

Godot 4.7.2, GDScript со статической типизацией, тесты GUT, GDExtension с этапа 5. Команды для macOS, терминал **fish**.

```fish
brew install --cask godot                 # установка
godot --path . --editor                   # редактор
godot --path .                            # запуск оверлея
godot --headless --path . -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit   # тесты (GUT 9.7.1)
```

## Код-стайл и соглашения

- Типизировано всё: `var x: int`, типы аргументов и возврата, типизированные сигналы.
- Модули общаются через `EventBus`, а не прямыми ссылками.
- Каждое состояние героя — отдельный скрипт с `enter()/exit()/update()/handle_input()`.
- Платформозависимое — только в `scripts/platform/` и `native/`. Недоступная фича тихо выключается.
- Числа баланса — только в ресурсе `.tres`.
- Архитектурные решения и их причины — в `docs/DECISIONS.md`.

## Правила

**Общение**

- Всегда общайся на русском и коротко объясняй, что делаешь и зачем.
- В конце каждого этапа: что сделано, как проверить руками, что осталось, известные проблемы.
- Все команды для пользователя — в синтаксисе fish: `set -x VAR value` вместо `export`, `; and` вместо `&&`.

**Git**

- Разрешены все операции, кроме `git push` в любом виде. Push делает только пользователь: когда пора пушить, дай ему готовую команду.
- **В начале каждой сессии, до любой работы, спроси режим коммитов** через AskUserQuestion (если недоступен — текстом): «Коммичу сам» или «Даю команды». Ответ действует до конца сессии. В режиме «Даю команды» вместо коммита выдавай готовые `git add` / `git commit`. Остальные git-операции выполняй сам в любом режиме.
- Коммиты делает только главная сессия (lead). Сабагенты в git ничего не записывают.
- Сообщения: Conventional Commits на английском, одна строка до ~60 символов в повелительном наклонении (`feat: add web swinging`, `fix(hero): clamp position to screen`), при необходимости 1–3 строки тела.
- **Никогда** не добавляй `Co-Authored-By`, «Generated with Claude Code», эмодзи и любые упоминания ИИ.

**Жёсткие ограничения продукта**

- Персонаж полностью оригинальный. Никаких отсылок к Marvel, Человеку-пауку и другим чужим персонажам: ни в арте, ни в названиях, ни в цветовой схеме-копии, ни в ассетах из интернета.
- Приложение никогда не ходит в сеть. Никакой телеметрии, аналитики, автообновлений.
- Файлы пользователя никогда не удаляются навсегда. Только `OS.move_to_trash()`.
- Не переходи к следующему этапу из `docs/SPEC.md`, пока пользователь не подтвердил текущий.

## Команда агентов

| Агент | Зона ответственности | Запрещено |
|---|---|---|
| `architect` | Дизайн модулей и интерфейсов, разбивка этапов, `.claude/team/*`, `docs/DECISIONS.md` | Продакшн-код, git |
| `godot-dev` | Сцены и GDScript: герой, паутина, UI, игровая логика | Тесты, `native/`, git |
| `native-dev` | `scripts/platform/`, `native/`, экспорт, сборка, CI | Игровая логика, тесты, git |
| `qa-tester` | Тесты GUT, замеры, чек-листы ручной проверки | Продакшн-код, git-записи |
| `security-auditor` | Аудит: сеть, файлы, сохранения, разрешения, нативный код, ассеты | Править и запускать код |
| `code-reviewer` | Ревью диффа, только чтение git | Править код, git-записи |

## Протокол сообщений

Агенты передают работу файлами в `.claude/messages/`, полное описание — в `.claude/messages/README.md`. Имя: `YYYYMMDD-HHMMSS_<from>_to_<to>_<T-xxx>.md`. Обработал сообщение — ставь `status: done`. Сообщения ссылаются на файлы и строки, а не дублируют код.

## Рабочий цикл

Ведёт главная сессия (lead):

1. Lead берёт задачу из `PLAN.md`, при необходимости просит `architect` уточнить дизайн.
2. `godot-dev` или `native-dev` реализует → `handoff` для `qa-tester`.
3. `qa-tester` пишет и гоняет тесты → `bug` исполнителю или `report` для lead.
4. Если задача касается файлов пользователя, сохранений, системных разрешений, `OS.execute`, нативного кода или новых зависимостей — `security-auditor`.
5. `code-reviewer` смотрит дифф → `review` для lead.
6. Lead сводит итог для пользователя и по режиму сессии коммитит сам или даёт команды в fish. Push — только командой для пользователя.

Независимые задачи lead может отдавать агентам параллельно. Поведение оверлея проверяет пользователь руками, поэтому каждый этап заканчивается чек-листом.
