# DeskHero — техническое задание

## 1. Суть проекта

DeskHero — кросс-платформенный десктопный питомец. Персонаж — **маленький оригинальный супергерой-паутинщик** (собственный дизайн: свои цвета, символ, маска/шлем). Он живёт поверх всех окон, ходит по краям экрана, стреляет паутиной, раскачивается, сидит на заголовках окон, реагирует на мышь, время, батарею, нагрузку, имеет потребности и развивается.

Цель — **максимум интерактива** и ощущение живого существа при минимальной нагрузке на компьютер.

Распространение: только через GitHub-репозиторий (готовые сборки в Releases + сборка из исходников одной командой). Никаких серверов и сети.

## 2. Платформы

| Платформа | Приоритет | Примечание |
|---|---|---|
| macOS 13+ (Apple Silicon и Intel) | Основная | Разработка и тесты идут здесь |
| Windows 10/11 | Вторая | Должно работать полностью |
| Linux X11 | Третья | Wayland — «как получится», без гарантий позиционирования поверх окон |

## 3. Стек

- **Godot 4** (актуальная стабильная 4.x), **GDScript** со статической типизацией (`var x: int`, типизированные сигналы и функции). C# не используем.
- **GUT** — юнит-тесты для логики (потребности, машина состояний, сохранения, таймеры).
- **GDExtension** (C++ через godot-cpp или Rust через godot-rust — выбрать на этапе 5 и обосновать) — только для того, чего нет в Godot: список чужих окон, системный idle, батарея, CPU.
- **GitHub Actions** — сборка под все платформы по git-тегу.

## 4. Ключевое архитектурное решение: окно

**Основной подход (проверить первым делом, этап 0):** одно прозрачное окно без рамки, поверх всех, на всю **рабочую область** экрана (без меню-бара/Dock/панели задач). Клики проходят сквозь окно везде, кроме героя и его интерактивных элементов: `mouse_passthrough_polygon` пересчитывается каждый кадр по контуру героя (и паутины, если её можно хватать).

Плюсы: герой свободно перемещается, паутина рисуется через весь экран, раскачка между окнами выглядит естественно.

**Запасной подход:** маленькое окно, которое двигается вместе с героем. Используем, только если основной на macOS даёт неустранимые проблемы (тормоза, мерцание, перехват кликов, конфликт с полноэкранными приложениями). Решение зафиксировать в `docs/DECISIONS.md`.

Требования к окну:
- не перехватывает клики вне героя;
- не появляется в Dock / Cmd+Tab (macOS: `LSUIElement` в Info.plist) и в панели задач (Windows);
- виден на всех рабочих столах macOS (Spaces);
- корректно работает при Retina / масштабе 125–200% на Windows;
- мульти-мониторы: на этапе 0 — только основной монитор, архитектура не должна мешать добавить остальные позже.

Принципы:
- Поведение героя — **иерархическая машина состояний**, каждое состояние отдельным скриптом с `enter()/exit()/update()/handle_input()`.
- Модули общаются через `EventBus`, а не прямыми ссылками.
- Всё платформозависимое — только в `scripts/platform/` и `native/`, с заглушками для неподдерживаемых ОС (фича тихо выключается, приложение не падает).
- Числа баланса (скорость голода, сила прыжка, длина паутины) — в одном ресурсе `.tres`, не в коде.

## 6. Персонаж и арт

- На этапах 0–3 — **плейсхолдер**: простой силуэт из примитивов или минимальные спрайты, чтобы не тормозить механики.
- Финальный арт — **скелетная (cutout) анимация** через `Skeleton2D` + `AnimationPlayer`: голова, торс, руки, ноги отдельными частями. Это позволяет делать много анимаций без перерисовки.
- Размер героя на экране ~64–96 px по высоте, настраивается.
- Анимации (минимальный набор): idle, idle_bored, walk, run, jump, fall, land, hang (на нитке), swing, shoot_web, climb, sit, sleep, happy, angry, sad, eat, carried (когда держат мышкой), thrown.
- Эмоции дополнительно показываются пузырями/иконками над головой.
- Гайд по дизайну персонажа вести в `docs/ART.md`.

## 7. Функциональность

### 7.1 Мышь и курсор
- Перетаскивание героя, бросок с инерцией, падение с физикой, обида после жёсткого приземления.
- Поглаживание: медленное движение курсора над героем → мурлыканье/радость; частые быстрые клики → раздражение.
- Погоня за курсором, иногда «ловит» его паутиной (визуально, курсор не блокируем).
- Двойной клик → радиальное меню: покормить, поиграть, спать, трюк, настройки.

### 7.2 Паутина
- Выстрел паутиной к краям экрана и (с этапа 5) к окнам.
- Раскачка — физический маятник (`PinJoint2D` / `DampedSpringJoint2D` или своя верлетовская верёвка — выбрать и обосновать в DECISIONS.md).
- Спуск на нитке с верхнего края экрана, нитку можно тянуть — пружинит.
- Плетение паутины в углах при долгом простое; паутину можно смахнуть курсором.

### 7.3 Окна (этап 5)
- Получение списка видимых окон и их прямоугольников (macOS `CGWindowListCopyWindowInfo`, Windows `EnumWindows` + `DwmGetWindowAttribute`, Linux X11 `_NET_CLIENT_LIST`).
- Сидит/ходит по заголовкам окон; окно двигают — едет вместе с ним; окно закрыли — падает и спасается паутиной.
- Раскачка между окнами, прятки за окнами с выглядыванием.
- Если для чего-то нужно системное разрешение (macOS «Универсальный доступ» / «Запись экрана») — фича опциональна, с понятным объяснением в настройках, без разрешения приложение работает в режиме «только края экрана».

### 7.4 Система
- Время суток: утро — зевает, ночь — спит, ворчит, если пользователь засиделся.
- Простой пользователя (idle): засыпает, при возвращении радуется.
- Батарея: низкий заряд — вялость, «слабая паутина»; зарядка — бодрость.
- Нагрузка CPU: при высокой — бегает и «тушит пожары».
- Опрос системы редкий (раз в 5–60 с в зависимости от метрики), не каждый кадр.
- Реакция на набор текста — **опционально, выключено по умолчанию** (требует «Мониторинг ввода» на macOS).

### 7.5 Файлы
- Перетащить файл на героя → он заворачивает его в кокон → `OS.move_to_trash()`. Сигнал `files_dropped` окна.
- Перед первым использованием — однократное подтверждение, что файлы уходят в корзину.

### 7.6 Потребности и развитие
- Голод, настроение, энергия; меняются со временем, **включая время, пока приложение было закрыто** (по сохранённому timestamp, с ограничением, чтобы герой не «умирал» за отпуск).
- Рост уровней, разблокировка трюков (двойной прыжок, батут из паутины, раскачка через весь экран и т.д.).
- Характер: накопительные параметры (ласковый/нервный/игривый) от того, как с ним обращаются; влияют на выбор поведения.
- Память о событиях («тебя не было 3 дня»).

### 7.7 Мини-игры и полезное
- Поймай-подбрось, прятки по экрану, поймай жуков паутиной.
- Помодоро-таймер: герой «работает» рядом и требует перерыв.
- Напоминания: приходит с запиской.

### 7.8 Системная интеграция
- Иконка в трее/меню-баре (`StatusIndicator`): показать/спрятать, пауза, настройки, выход.
- Автозапуск при входе в систему (опция).
- Окно настроек: размер героя, громкость, частота «приставаний», включение опциональных фич.

## 8. Нефункциональные требования

- **Производительность:** в покое < 1–2% CPU на M1. Ограничение FPS: 30 при активности, 5–10 в покое/сне, `low_processor_mode` где возможно.
- **Стабильность:** ни одна недоступная платформенная фича не роняет приложение.
- **Сохранения:** в `user://`, JSON с полем `schema_version` и миграциями; запись атомарная (во временный файл → переименование).
- **Без сети**, без телеметрии.
- **Логи** в `user://logs/` с ротацией.

## 9. Сборка и распространение

- `tools/build.fish` — локальная сборка под текущую ОС одной командой (экспорт через `godot --headless --export-release`).
- GitHub Actions по тегу `v*`: macOS (universal `.dmg`/`.zip`), Windows (`.zip` с `.exe`), Linux (`.AppImage` или `.tar.gz`) → в GitHub Releases.
- Подписи нет. В README — понятная инструкция для macOS (Gatekeeper: «Конфиденциальность и безопасность → Всё равно открыть» или `xattr -dr com.apple.quarantine /Applications/DeskHero.app`) и Windows (SmartScreen: «Подробнее → Выполнить в любом случае»), плюс вариант сборки из исходников, где этих предупреждений нет.

## 10. Этапы

Каждый этап заканчивается: работающим запуском, ручным чек-листом проверки, тестами для логики (где применимо), обновлённым README/DECISIONS, готовыми git-командами для меня. **Следующий этап — только после моего подтверждения.**

**Этап 0 — Спайк окна (самое рискованное, делаем первым).**
Прозрачный оверлей на рабочую область, поверх всех окон, клики сквозь всё, кроме квадрата-плейсхолдера, который можно таскать. Нет иконки в Dock/Cmd+Tab, виден на всех Spaces. Замер CPU. Итог — решение в DECISIONS.md: основной подход или запасной.
*Готово, когда:* я могу работать в других приложениях как обычно, а квадрат таскается и не мешает.

**Этап 1 — Герой и физика.**
Плейсхолдер-персонаж, гравитация, ходьба по нижнему краю, перетаскивание, бросок, приземление, машина состояний (idle/walk/fall/carried/thrown/land), базовые эмоции. Ресурс баланса.

**Этап 2 — Паутина.**
Выстрел к краям экрана, раскачка, висение на нитке, натяжение, плетение в углах и смахивание.

**Этап 3 — Потребности, сохранения, меню.**
Голод/настроение/энергия, офлайн-изменения, сохранения с версией схемы, радиальное меню, трей, настройки, автозапуск. Тесты GUT.

**Этап 4 — Реакции на систему.**
Время суток, idle, батарея, CPU через `SystemProbe` (сначала через `OS.execute`-бэкенд на macOS, с заглушками на других ОС).

**Этап 5 — Окна.**
GDExtension для списка окон и системных метрик под macOS, затем Windows, затем Linux X11. Сидение на окнах, падение при закрытии, раскачка между окнами, прятки.

**Этап 6 — Файлы.**
Drag-and-drop файла, кокон, корзина, подтверждение.

**Этап 7 — Мини-игры и полезности.**
Поймай-подбрось, прятки, жуки, помодоро, напоминания.

**Этап 8 — Развитие и характер.**
Уровни, трюки, характер, память о событиях.

**Этап 9 — Финальный арт.**
Скелетная анимация героя по `docs/ART.md`, звуки, полировка.

**Этап 10 — Релиз.**
GitHub Actions, README с инструкциями установки, проверка чистой установки на каждой ОС.

## 11. Чего не делаем

- Разговор через нейросеть (локальную или облачную).
- Любые сетевые функции.
- Персонажей, похожих на чужие (Marvel и т.п.).
- Wayland-специфичные обходы до релиза.
